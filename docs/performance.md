# 性能优化与验证

验证日期：2026-11-05，Windows x64。

## 已落实的九项优化

| 项目          | 实现与边界                                                                                                                                                                                            |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 读取任务取消  | 相同读取共享执行，每个界面独立释放订阅。关闭仓库、切换文件及离开历史界面会取消不再需要的读取；Rust 将取消信号传给并行工作线程，并终止对应的本地 Git / OpenSSH 读取进程。Git 写操作继续执行到完成。    |
| 局部刷新      | 暂存和取消暂存只执行状态读取；远程地址修改只刷新远程信息；删除分支和推送只刷新分支；Fetch 刷新提交和分支。其余操作完整刷新。局部更新保留未变化的数据引用，避免重置提交历史。                          |
| 缓存预算      | 快照最多 8 个、估算数据体积 16 MiB；详情最多 64 条、估算数据体积 8 MiB。采用 LRU，5 分钟过期，每分钟清理过期项。关闭仓库立即移除所属缓存。预算根据对象内容估算，不代表整个 WebView 的内存上限。       |
| 历史浏览      | 保留最多 1,000 条提交。向后加载时释放前面的数据，可通过“加载前面的提交”重新读取。分页使用绝对偏移。图布局的工作量受窗口大小约束，图边使用区间索引查询可见部分。搜索范围仍为当前加载的提交。           |
| 长列表和 Diff | 超过 80 项的变更文件、提交文件、分支、远程列表使用虚拟渲染；分支选择器同样适用。Diff 只挂载可见行及预留行，以 Uint32Array 保存换行位置，避免为每行长期保存一个字符串。原有 Git 输出体积限制继续生效。 |
| React 渲染    | 提交选择回调保持稳定，保留 CommitRow 的 memo 效果；i18n Context 的值保持稳定。                                                                                                                        |
| 配置写入      | 配置变更在内存中更新，300 毫秒内合并持久化；指针释放、页面隐藏和退出页面时刷新待保存值。拖动面板期间不再每次移动都序列化写盘。                                                                        |
| 状态扫描      | 默认使用 Git 的未跟踪目录摘要模式。点击目录或“展开未跟踪文件夹”后读取单个文件，仍可直接暂存整个目录。此模式减少文件枚举与传输，不保证所有仓库的磁盘扫描都能完全省略。                                 |
| 头像资源      | 批量和单项写入共用 256 项缓存限制，清理过期记录，并限制预热标记与恢复的数据。离开仓库时取消相关的网络请求和排队任务，保留跨仓库共享的已验证身份信息。                                                 |

## 关闭仓库

- 后台读取期间允许关闭，Git 写操作执行期间继续保持保护。
- 关闭后立即更新列表和当前视图。下一仓库有缓存时先显示缓存，再刷新。
- 取消尚未完成的打开操作，避免旧结果重新打开已经关闭的仓库。
- 终端关闭在后台释放进程和 PTY；创建终端时不再持有会话表的锁。面板在认证期间被关闭后，不再继续创建终端。

## 自动验证

在项目根目录执行：

```powershell
node --test --test-concurrency=1 tests/*.test.mjs
$env:RAYON_NUM_THREADS='1'
npm run build
cargo test --manifest-path src-tauri/Cargo.toml -j 1 -- --test-threads=1
```

本次结果：31 项前端测试通过；35 项 Rust 单元测试、3 项凭据集成测试通过。另有 3 项需要外部配置的测试按原有设置跳过。TypeScript 检查与前端生产构建通过。

严格 Clippy 检查仍报告 4 处既有的 `collapsible_if` 风格告警，位于未在本次修改的 `accounts.rs` 和 `oauth.rs`。测试与构建不受这些告警影响。

本次机器曾出现系统提交内存不足，串行测试及限制构建线程后完成了验证。上面的环境变量只影响当前 PowerShell 会话，没有修改系统配置。

## 界面压力验证

`tests/performance-ui.mjs` 会启动临时本地 HTTP 服务，在系统 Edge 无头浏览器中加载生产构建。IPC 使用模拟数据，不操作真实仓库。需事先准备 Playwright；可以安装到项目外的临时目录，避免变更项目依赖：

```powershell
$qaRoot=Join-Path $env:TEMP 'repoweft-performance-qa'
npm install --prefix $qaRoot --no-package-lock --no-audit --no-fund playwright
$env:REPOWEFT_PLAYWRIGHT_MODULE=Join-Path $qaRoot 'node_modules/playwright/index.mjs'
node tests/performance-ui.mjs
```

本次场景与结果：

- 100,000 行 Diff 实际挂载 46 行，可滚动到末行。
- 10,000 个工作区文件、5,000 个提交文件和 1,000 个分支均保持有限数量的 DOM 节点，分支搜索可定位末项。
- 连续加载超过 1,000 条提交后可以向前加载。
- 模拟慢速刷新期间可连续关闭两个仓库；读取被取消，迟到结果没有恢复仓库视图。
- 一次关闭点击到侧栏条目移除耗时约 47 毫秒，控制台无运行错误。
- 强制 GC 后，初始 JS 堆约 4.12 MB；关闭全部仓库后约 5.84 MB。这是单次界面测试观察值，不代表应用整体进程内存，也不构成与旧版本的内存降幅对比。
- 界面截图写入系统临时目录 `repoweft-large-diff.png`，测试结束会关闭浏览器和本地服务。

尚未测量真实大型仓库、真实 SSH 网络延迟以及 Release 原生窗口完整进程组的前后内存差异。Rust 测试已覆盖真实临时仓库、读取进程取消和 PTY 释放；界面压力数据采用模拟 IPC。
